### 1. 수취인 성명 조회 API

<span className="api-post">POST</span> [`{API 도메인}`](/guide/overview#api-도메인)`/inquiry/real-nam`

은행코드 및 계좌번호를 토대로 수취인 성명 조회 후 이용기업에 다시 전달합니다. \
이용기업에서는 수취인 성명조회 결과값과 회원명 일치여부 확인 후 결과에 따라 아래와 같이 표시 요청합니다.

- 회원명과 일치 시 ARS 인증 안내메시지30 표시 : ARS를 통한 자동이체 출금동의를 진행합니다. \
  이용기업 서비스명 입력 위한 자동이체 계좌 등록에 동의하시면 안내음성에 따라 인증번호를 입력하세요.

- 회원명과 불일치 시 오류메시지 표시 : 회원 본인 명의의 계좌만 등록할 수 있습니다.

#### 요청 파라미터

| 필드명     | 타입     | 필수 | 길이 | 설명                      |
| ---------- | -------- | ---- | ---- | ------------------------- |
| `mchtTrNo` | `String` | Yes  | 50   | 가맹점거래번호            |
| `trTime`   | `String` | Yes  | 14   | 거래일시 (YYYYMMDDHHMMSS) |
| `mid`      | `String` | Yes  | 10   | 이용기관코드              |
| `bankCd`   | `String` | Yes  | 3    | 출금은행코드              |
| `acctNo`   | `String` | Yes  | 16   | 출금계좌번호              |

#### 요청 예시

<CodeBlock> 
```json
{
  "mchtTrNo": "123456789",
  "trTime": "20220401130101",
  "mid": "C123456789",
  "bankCd": "090",
  "acctNo": "1234567891012345"
}
```
</CodeBlock>

#### 응답

| 필드명     | 타입     | 필수 | 길이 | 설명           |
| ---------- | -------- | ---- | ---- | -------------- |
| `resCd`    | `String` | Yes  | 4    | 응답코드       |
| `resMsg`   | `String` | Yes  | 20   | 응답메세지     |
| `mchtTrNo` | `String` | Yes  | 50   | 가맹점거래번호 |
| `acctUser` | `String` | Yes  | 20   | 수취인성명     |

#### 응답 예시

<CodeBlock> 
```json
{
  "resCd": "0000",
  "resMsg": "정상",
  "mchtTrNo": "123456789",
  "acctUser": "예금주명"
}
```
</CodeBlock>

### 2. ARS 출금동의 API
<span className="api-post">POST</span> `{API 도메인}/withdraw/ars-agreement`

인증번호는 이용기업 회원의 생년월일 또는 이용기업에서 생성하는 임의의 숫자입니다.

- 인증번호는 ARS 인증 시 고객이 입력하는 번호, 최대 6자리까지 가능

결과코드가 정상일 경우 ARS 인증거래번호 전달, 오류일 경우 빈값으로 전달합니다.
개발환경에서 테스트 할 경우 반드시 테스트 계좌번호로 요청 해 주시길 바랍니다.

#### 요청 파라미터

| 필드명     | 타입     | 필수 | 길이 | 설명                                                   |
| ---------- | -------- | ---- | ---- | ------------------------------------------------------ |
| `mchtTrNo` | `String` | Yes  | 50   | 가맹점거래번호                                         |
| `trTime`   | `String` | Yes  | 14   | 거래일시 (YYYYMMDDHHMMSS)                              |
| `mid`      | `String` | Yes  | 10   | 이용기관코드                                           |
| `bankCd`   | `String` | Yes  | 3    | 출금은행코드                                           |
| `acctNo`   | `String` | Yes  | 16   | 출금계좌번호                                           |
| `birthDt`  | `String` | Yes  | 10   | 실명번호 개인:생년월일(YYMMDD) / 사업자:사업자등록번호 |
| `acctUser` | `String` | Yes  | 40   | 계좌 수취인명                                          |
| `phone`    | `String` | Yes  | 20   | 핸드폰번호                                             |
| `authNo`   | `String` | Yes  | 6    | ARS 인증번호                                           |

#### 요청 예시

<CodeBlock>
```json
{
  "mchtTrNo": "123456789",
  "trTime": "20220401130101",
  "mid": "C123456789",
  "bankCd": "090",
  "acctNo": "0123456789101234",
  "birthDt": 890101,
  "acctUser": "수취인명",
  "phone": "01099998888",
  "authNo": 123456
}
```
</CodeBlock>

#### 응답

| 필드명      | 타입     | 필수 | 길이 | 설명           |
| ----------- | -------- | ---- | ---- | -------------- |
| `resCd`     | `String` | Yes  | 4    | 응답코드       |
| `resMsg`    | `String` | Yes  | 20   | 응답메세지     |
| `mchtTrNo`  | `String` | Yes  | 50   | 가맹점거래번호 |
| `certTrxNo` | `String` | Yes  | 10   | 인증거래번호   |

#### 응답 예시

<CodeBlock> 
```json
{
  "resCd": "0000",
  "resMsg": "정상",
  "mchtTrNo": "123456789",
  "certTrxNo": "123456789"
}
```
</CodeBlock>

### 3. 출금계좌등록 API
<span className="api-post">POST</span> `{API 도메인}/account/register`

이용기업에서 출금동의 요청시 전달받은 인증거래번호를 자동이체 출금계좌등록 요청 시 필수 전달합니다.
이용기업에선 처리결과코드가 정상일 경우 납부자번호 전달, 오류일 경우 빈값 혹은 오류값 전달합니다.\
납부자 번호를 이용기관에서 일괄 관리할 경우는 필수로 채워주시고,
이용기관이 아닌 KICC에서 채번된 납부자 번호를 이용하실 경우, **KICC_PAYER_NO** 값을 채워주시면 됩니다.\
(두가지 방식을 혼용해서 사용하시는 일은 없도록 주의)\
KICC 채번 방식일 경우, 응답전문에 내려드린 `payerNo` (납부자번호)로 출금요청API 요청하셔야 됩니다.

#### 요청 파라미터

| 필드명      | 타입     | 필수 | 길이 | 설명                      |
| ----------- | -------- | ---- | ---- | ------------------------- |
| `mchtTrNo`  | `String` | Yes  | 50   | 가맹점거래번호            |
| `trTime`    | `String` | Yes  | 14   | 거래일시 (YYYYMMDDHHMMSS) |
| `mid`       | `String` | Yes  | 10   | 이용기관코드              |
| `certTrxNo` | `String` | Yes  | 10   | 인증거래번호              |
| `payerNo`   | `String` | Yes  | 20   | 납부자번호                |

#### 요청 예시

<CodeBlock> 
```json
{
  "mchtTrNo": "123456789",
  "trTime": "20220401130101",
  "mid": "C123456789",
  "certTrxNo": "1234567890",
  "payerNo": "KICC_PAYER_NO"
}
```
</CodeBlock>

#### 응답

| 필드명     | 타입     | 필수 | 길이 | 설명           |
| ---------- | -------- | ---- | ---- | -------------- |
| `resCd`    | `String` | Yes  | 4    | 처리결과코드   |
| `resMsg`   | `String` | Yes  | 40   | 결과메시지     |
| `mchtTrNo` | `String` | Yes  | 50   | 가맹점거래번호 |
| `payerNo`  | `String` | Yes  | 20   | 납부자번호     |

#### 응답 예시

<CodeBlock> 
```json
{
  "resCd": "0000",
  "resMsg": "정상",
  "mchtTrNo": "123456789",
  "payerNo": "C00000000000000000"
}
```
</CodeBlock>

### 4. 1원이체 API
<span className="api-post">POST</span> `{API 도메인}/deposit/1won`

이용기업에서 출금동의 요청시 전달받은 `certTrxNo` (인증거래번호) 와 `acctName` (의뢰인명) 항목에 가상의 입금자명을 랜덤으로 생성 후 전달 및 요청합니다.\
`acctName` (가상의 입금자명) : 이용기업에서 랜덤으로 생성(원하는 가상의 입급자명을 넣어서 전달요청)\
전달된 가상의 입금자명은 고객 통장적요에 입력하여 진행합니다.\
이용기업에선 `acctName` (가상의 입금자명)을 통해 지급이체 인증 확인 진행합니다.\
(이용기업에서는 처리결과코드에 따라 아래와 같이 표시)

1. `resCd`(결과코드)가 `0000` (정상) 일 경우, 1원 입금 통장적요에 입력된 값을 화면에 입력하세요.\
   1-1. 이용기업에서 전달한 가상의 입금자명과 회원이 입력한 값이 같으면 -> 자동이체 출금계좌 등록 진행\
   1-2. 이용기업에서 전달한 가상의 입금자명과 회원이 입력한 값이 다르면 -> 지급이체 다시 진행 혹은 종료
2. `resCd`(결과코드)가 `R000` (오류일 경우, 오류 메시지 표시)

#### 요청 파라미터

| 필드명      | 타입     | 필수 | 길이 | 설명                      |
| ----------- | -------- | ---- | ---- | ------------------------- |
| `mchtTrNo`  | `String` | Yes  | 50   | 가맹점거래번호            |
| `trTime`    | `String` | Yes  | 14   | 거래일시 (YYYYMMDDHHMMSS) |
| `mid`       | `String` | Yes  | 10   | 이용기관코드              |
| `certTrxNo` | `String` | Yes  | 10   | 인증거래번호              |
| `acctName`  | `String` | Yes  | 20   | 입금자명                  |

#### 요청 예시

<CodeBlock> 
```json
{
  "mchtTrNo": "123456789",
  "trTime": "20220401130101",
  "mid": "C123456789",
  "certTrxNo": "12345678910",
  "acctName": "가상의 입금자명"
}
```
</CodeBlock>

#### 응답

| 필드명     | 타입     | 필수 | 길이 | 설명            |
| ---------- | -------- | ---- | ---- | --------------- |
| `resCd`    | `String` | Yes  | 4    | 처리결과코드    |
| `resMsg`   | `String` | Yes  | 40   | 결과메시지      |
| `mchtTrNo` | `String` | Yes  | 50   | 가맹점거래번호  |
| `acctName` | `String` | Yes  | 20   | 가상의 입금자명 |

#### 응답 예시

<CodeBlock> 
```json
{
  "resCd": "0000",
  "resMsg": "정상처리",
  "mchtTrNo": "123456789",
  "acctName": "입금자명"
}
```
</CodeBlock>

### 8. 출금계좌해지 API
<span className="api-post">POST</span> `{API 도메인}/account/cancel`

등록된 출금계좌 해지 작업합니다.
납부자 번호가 KICC 채번 방식일 경우, 출금계좌등록 응답전문에 수신받은 `payerNo` (납부자번호)로 올려야 됩니다.

#### 요청 파라미터

| 필드명      | 타입     | 필수 | 길이 | 설명                      |
| ----------- | -------- | ---- | ---- | ------------------------- |
| `mchtTrNo`  | `String` | Yes  | 50   | 가맹점거래번호            |
| `trTime`    | `String` | Yes  | 14   | 거래일시 (YYYYMMDDHHMMSS) |
| `mid`       | `String` | Yes  | 10   | 이용기관코드              |
| `certTrxNo` | `String` | Yes  | 10   | 인증거래번호              |
| `payerNo`   | `String` | Yes  | 20   | 납부자번호                |

#### 요청 예시

<CodeBlock> 
```json
{
  "mchtTrNo": "123456789",
  "trTime": "20220401130101",
  "mid": "C123456789",
  "certTrxNo": "1234567890",
  "payerNo": "C00000000000000000"
}
```
</CodeBlock>

#### 응답

| 필드명     | 타입     | 필수 | 길이 | 설명           |
| ---------- | -------- | ---- | ---- | -------------- |
| `resCd`    | `String` | Yes  | 4    | 처리결과코드   |
| `resMsg`   | `String` | Yes  | 40   | 실패메시지     |
| `mchtTrNo` | `String` | Yes  | 50   | 가맹점거래번호 |

#### 응답 예시

<CodeBlock> 
```json
{
  "resCd": "0000",
  "resMsg": "정상",
  "mchtTrNo": "123456789"
}
```
</CodeBlock>
